# PC e código por voz

[← Jarvis](README.md)

No PC, o Jarvis é o **Claude Code**: você ativa o `/voice`, fala o pedido e ele executa com as ferramentas que já tem (arquivos, terminal, git, pesquisa na web, servidores MCP). O hook `falar.py` faz ele responder em voz.

## Ligar a voz de volta (passo jv-claude-voz)

No Ubuntu (linha `alanmateus@...$`):

```bash
pipx install piper-tts
mkdir -p ~/.local/share/piper   # baixe aqui o pt_BR-faber-medium.onnx e o .onnx.json do repositório de vozes do Piper
python3 ~/dev/dev-setup/tools/jarvis/falar.py --teste
```

Depois, em `~/.claude/settings.json`:

```json
{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command", "command": "python3 ~/dev/dev-setup/tools/jarvis/falar.py" } ] }
    ]
  }
}
```

Para silenciar sem mexer no arquivo: `export JARVIS_MUDO=1`. O hook nunca trava o Claude Code: sem Piper ou sem som, ele só não fala.

## O que dá para pedir

| Você fala | O que ele faz |
|---|---|
| "Cria a pasta da aula de quinta de Lógica e copia o modelo da escola" | Pastas e arquivos no repositório de aulas |
| "Organiza os downloads" | Roda o `tools/organizar/downloads.py` e mostra o que vai mover antes |
| "Procura crackmes de nível fácil para estudar" | Pesquisa na web e lista crackmes.one, OWASP MAS e afins (só desafios feitos para isso) |
| "Acha um repositório de referência de monólito modular em .NET e clona" | Pesquisa, mostra as opções e clona o que você escolher em `~/dev/referencias` |
| "Quero contribuir com o ESPHome, acha uma issue boa para começar" | Lista issues `good first issue`, explica a escolhida e prepara o ambiente |
| "Roda os testes e me diz o que quebrou" | Testes, leitura do erro e proposta de correção |
| "Qual o próximo passo do roteiro?" | `tools/sessao/contexto.py --resumo` |

## Contribuir em open source (passo jv-opensource)

1. Escolher um projeto que você usa (Home Assistant, ESPHome, Ghidra, uma biblioteca .NET).
2. Ler o `CONTRIBUTING.md` e a **regra de uso de IA** do projeto: vários exigem dizer que houve ajuda de IA, e alguns não aceitam.
3. Pegar uma issue `good first issue`, comentar que vai fazer, fazer o fork.
4. O agente prepara branch, código e testes; **você revisa linha por linha** e roda tudo.
5. Abrir o PR com a descrição no padrão do projeto. O PR é seu: você responde às revisões.

Uma contribuição aceita por mês vale mais no currículo do que dez abertas e abandonadas.

## Limites no PC

- O agente roda dentro do **ai-jail** (só enxerga a pasta do projeto) e pede confirmação antes de apagar, publicar, fazer push ou mandar mensagem em seu nome.
- Pesquisa para engenharia reversa: só alvos feitos para isso ou seus. Ele recusa "quebrar" software pago, e isso é bom.
- Voz não substitui revisão: o que ele faz por voz você confere na tela antes de commitar.
