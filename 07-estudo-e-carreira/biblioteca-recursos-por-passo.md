# Biblioteca de Recursos — O Que Ler/Assistir em Cada Passo
### Organizado na mesma ordem do `passo-a-passo-mestre` — abra o passo, encontre a leitura certa aqui, sem procurar sozinho

---

## Como usar este documento

Pra cada tecnologia/conceito, 1-3 recursos **verificados**, não uma lista genérica de "aprenda X" — sempre a fonte oficial primeiro, depois um complemento prático. Onde já existe curso pago que você usa (Rocketseat/Alura, já decidido em conversa anterior), não repito aqui — só o que é gratuito e específico.

## roadmap.sh — auditoria cruzada, não recurso de um passo só

Diferente do resto desta biblioteca (recurso específico de um passo), o roadmap.sh serve **todo o plano** — é um checklist visual da comunidade, gratuito, pra conferir se algo ficou de fora. Confirmado como site real e ativo (6º projeto mais estrelado do GitHub).

| Roadmap | Link confirmado | Use no momento de |
|---|---|---|
| Índice geral (todos os roadmaps disponíveis) | [roadmap.sh/roadmaps](https://roadmap.sh/roadmaps) | Sempre que precisar achar o roadmap certo de uma tecnologia nova |
| Backend | [roadmap.sh/backend](https://roadmap.sh/backend) | Passos 3-8 |
| ASP.NET Core | [roadmap.sh/aspnet-core](https://roadmap.sh/aspnet-core) | Passos 3-5, específico do seu framework |

Pra PostgreSQL, Docker, System Design, C, C++, Git/GitHub, SQL, DevOps, Kubernetes — todos existem no site, mas em vez de arriscar um link exato que pode mudar, busque pelo nome direto em [roadmap.sh/roadmaps](https://roadmap.sh/roadmaps) no momento do Passo correspondente (ex: Passo 8B → buscar "C" e "C++" lá).
